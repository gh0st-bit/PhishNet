# PhishNet local feature audit — 9 November 2026

Historical snapshot. See the [10 November follow-up](qa-role-review-2026-11-10.md)
for completed fixes, role tests and persistent accounts for manual verification.

The app is running at http://localhost:5000 in the isolated `phishnet_audit`
environment. Test data and disposable tenants were used. Real mail delivery is
disabled. Existing audit-account passwords were preserved.

## Fixed

- **Enter on login opens recovery:** marked the recovery button as `type="button"`.
  Enter now signs in from either the email or password field.
- **Sidebar jumps to the top:** preserve scroll position and expanded sections
  per signed-in user when page layouts remount. Navigation and browser Back keep
  the menu position.

Both fixes have passing browser regression tests in
`tests/browser/navigation-regressions.spec.ts`.

## Confirmed remaining issues

| Priority | Area | Reproduction / observed result | Proposed solution |
| --- | --- | --- | --- |
| Critical | Encryption key rotation | In a disposable tenant, encrypt a value, rotate the tenant key using the API, then decrypt the previous value. Rotation returns success but decryption fails. | Re-encrypt all protected fields with the replacement key and switch keys atomically, with rollback and recovery. Until implemented, disable the rotation action. |
| High | Training module creation | Submit the actual Create Module form. HTTP 400 requires `organizationId` and `createdBy`, although the server sets them from the session. | Omit server-managed fields from the create request schema; derive them from the authenticated user. |
| High | Quiz creation | Submit the actual Create Quiz form. Same HTTP 400 for `organizationId` and `createdBy`. | Use a request schema without server-managed fields. |

| Medium | Content → Videos | Add New Video is disabled; the page always displays a placeholder, even with an existing training module/video. | Connect this screen to training-module video management or replace it with a link to the working management area. |
| Medium | Content → MCQs | Add New MCQ is disabled; existing quiz questions never appear here. | Implement the question-bank workflow or connect this screen to quiz question management. |
| Medium | Employee Flashcards navigation | Decks and cards work, but the page omits the shared sidebar/header/main layout. | Wrap all loading, deck-selection and study states in `AppLayout`. |
| Medium | Employee article detail navigation | Published article content displays, but its detail page omits the shared sidebar/header/main layout. | Wrap article-detail, loading and error states in `AppLayout`. |

The training/quiz API cycles continued using explicit fixture-only values for
the missing server-managed fields. This allowed downstream assignment,
completion, publishing and scoring to be tested; it does **not** mean normal

## Limits

This verifies local data workflows and selected browser interactions, not every
possible input, permission combination or concurrent operation. Actual SMTP/
SendGrid delivery, public DNS ownership verification, SAML identity-provider
login, live AI/contact providers, live threat-feed ingestion and production
capacity were not certified. Contact-provider status reports Apollo and
RocketReach unavailable. A configured Gemini key alone does not establish a
working integration. Test email remains in the sink. Threat and operations
dashboards received read/render checks rather than fabricated live-provider
results.

Reproduce the local checks from the project root:

```powershell
$env:E2E_BROWSER_CHANNEL = 'chrome'
node scripts/run-audit.mjs browser
node scripts/feature-cycle-audit.mjs
node scripts/audit-ui-forms.mjs
node scripts/run-audit.mjs governance
```

The audit scripts return a failing exit code when they reproduce outstanding
defects. Browser/database process permissions may require running them outside
the Codex sandbox. They do not require changing the computer's permanent
PowerShell execution policy.
